fix(gpui-player): 点击歌词即时跳转——乐观更新 + seek 后即时补发位置

根因(此前探索已定位):PlayPosition 常规节奏 1s 一拍,SeekAudio 处
理器不回传位置,点击后 UI 只能继续外推旧位置等下一个 tick——平
均 ~500ms、最坏 1000ms 的"慢半拍"。

三层修复:
1. lyric_page.seek_to:点击时乐观更新 event_position_ms 为目标行
   起点(上游浏览器对 audio.currentTime 的同款语义),下一帧歌词
   即跳、seek 弹簧(90/15)当帧起跳;
2. player-core SeekAudio 处理成功后立即补发一条 PlayPosition
   (counter 已清零,position 即真实位置)——消除乐观更新后的竞
   态:点击→处理完成之间撞上的旧位置 tick 会把 UI 拽回旧位置,
   补发把校正窗口压到毫秒级;
3. send_seek 噪声修复:消息通道是无界 mpsc(同步 send),复用首
   次调用创建的静态 runtime,不再每次点击新建线程+runtime。

端到端实测(真实点击自动化 + 时序日志):点击→补发回传
0.6ms/6ms/5.7ms,三次点击后常规 tick 均从新位置无缝续走
(16522←15952、28860←28530、47678←47568),零拽回。
63 测试全绿,clippy 零告警。Tauri 版同样受益于补发(纯增量
事件,无行为破坏)。
